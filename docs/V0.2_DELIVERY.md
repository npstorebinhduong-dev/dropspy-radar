# v0.2 delivery

Built incrementally on v0.1 and all six Phase 2 research documents, on `feat/dropspy-radar-v0.2-data-core` from `feat/active-ad-search-analysis`.

## Completed

- Six requested source categories plus disabled legacy-unknown preservation; capability/approval gates, market/corpus/filter/media/retention metadata. Live adapters disabled by default.
- Versioned PostgreSQL Alembic schema for sources, queries, runs, advertisers, ads, creatives, observations, raw evidence and import jobs. Existing v0.1 records and saved flags preserved.
- Bounded CSV/JSON upload, field mapping, preview and validation, explicit rights attestation, idempotent job creation, transactional batches, progress/retry/resume, downloadable errors, evidence retention and atomic deduplication.
- Search imported ads by platform, US/EU/country, keyword/domain, advertiser, status and observation dates, with sorting and pagination. Per-partition save/detail/evidence/analysis flows preserve original API routes.
- Original seven dashboard views retained; Settings data workspace plus dedicated Data Sources, Import and Import History pages. REAL/DEMO/UNKNOWN and corpus labels explicit.
- Source/run/observation provenance and original/normalized evidence. Source delivery dates remain separate from observation history. No inference that missing ads stopped; no external URL fetching or media archival during imports.
- Fixtures, unit/API/PostgreSQL concurrency/migration tests and Playwright dashboard regression. Compose startup applies migrations before serving.

## Deliberately incomplete / prerequisites

- No verified US live commercial ad source or approved production collector. Meta public visibility does not prove automated/commercial reuse permission; token/approval, current geographic scope and terms remain unverified. See [source feasibility](research/US_LIVE_SOURCE_FEASIBILITY.md).
- No actual permitted user dataset was supplied during this task. Tests demonstrate pipeline behavior, not live ad inventory, ROAS or revenue.
- Source approval management is read-only in UI and requires trusted operator administration; no credential management or automatic approval workflow.
- Imports currently cover US and EU27; 2 MiB / 2,000 rows per file. One local workspace, no user authentication/tenant isolation, no distributed queue or cancellation. Ports remain loopback; shared/public deployment needs authentication.
- Dataset attestation is recorded, not independently legally verified. Raw evidence expires under source policy; normalized ad projections remain retained. Preview rows expire after their configured TTL.
- Full/capped/partial run labels are retained; no automatic inactive deltas are generated. Product grouping, watchlists, AI and a new product score are deferred.
- GitHub API integration currently returns Forbidden; git branch push is separate from PR creation.
